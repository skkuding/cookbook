## 프로젝트 실습 🎈

지난주에 구현한 Restaurant CRUD API에 요청 데이터 검증, 예외 처리, Guard와 Unit Test를 추가해봅시다.

데이터베이스는 아직 사용하지 않으며, 기존과 동일하게 식당 데이터를 Service의 배열에 저장합니다.

### 1. DTO와 Validation

Restaurant 생성과 수정 요청에 사용할 DTO를 작성합니다.

먼저 필요한 패키지를 설치합니다.

```bash
pnpm add class-validator class-transformer
```

- `CreateRestaurantDto`
    - `name`, `address`, `phone`을 필수 값으로 받습니다.
- `UpdateRestaurantDto`
    - 수정할 값만 전달할 수 있도록 각 필드를 선택적 프로퍼티로 선언합니다.
    - 각 필드에 `@IsOptional()`을 적용합니다.
- `class-validator`를 사용하여 각 필드가 비어 있지 않은 문자열인지 검증합니다.
- `ValidationPipe`를 적용하여 올바르지 않은 요청은 거부합니다.

아래 자료를 참고하세요.

- **[Validation](https://docs.nestjs.com/techniques/validation)**
- **[class-validator](https://github.com/typestack/class-validator)**

### 2. Pipe와 예외 처리

- `GET /restaurants/:id`, `PATCH /restaurants/:id`, `DELETE /restaurants/:id`의 `id`에 `ParseIntPipe`를 적용합니다.
- 요청한 `id`에 해당하는 식당이 없다면 `NotFoundException`을 발생시킵니다.

아래 자료를 참고하세요.

- **[Pipes](https://docs.nestjs.com/pipes)**
- **[Exception Filters](https://docs.nestjs.com/exception-filters)**

### 3. Guard

식당 정보를 변경하는 API에 간단한 Guard를 적용합니다.

- 요청 헤더의 `x-api-key` 값을 확인하는 Guard를 작성합니다.
- API Key가 올바른 경우에만 다음 API를 사용할 수 있도록 합니다.
    - `POST /restaurants`
    - `PATCH /restaurants/:id`
    - `DELETE /restaurants/:id`
- API Key는 환경 변수에 저장하지 않고 실습을 위한 임의의 값으로 설정해도 됩니다.

아래 자료를 참고하세요.

- **[Guards](https://docs.nestjs.com/guards)**

### 4. Unit Test

Jest를 사용하여 `RestaurantsService`의 Unit Test를 하나 이상 작성합니다.

다음 항목 중 하나를 선택하여 테스트하세요.

- 전체 식당 목록을 반환하는지
- 새로운 식당이 정상적으로 추가되는지
- 존재하지 않는 식당을 조회했을 때 `NotFoundException`이 발생하는지

테스트 코드는 `restaurants.service.spec.ts`에 작성합니다.

- **[Testing](https://docs.nestjs.com/fundamentals/testing)**

### 5. API 테스트

Bruno를 사용하여 다음 내용을 확인합니다.

- 정상적인 요청이 처리되는지
- 잘못된 Body가 `ValidationPipe`에 의해 거부되는지
- 숫자가 아닌 `id`가 `ParseIntPipe`에 의해 거부되는지
- 존재하지 않는 식당을 요청했을 때 `NotFoundException`이 발생하는지
- API Key가 없거나 올바르지 않을 때 변경 요청이 거부되는지
- 이외에도 추가하고 싶은 부분이 있다면 자유롭게 추가해주세요!
